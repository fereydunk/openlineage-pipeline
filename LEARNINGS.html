Ranked by how likely it is to bite

The top ten

Numbered because they really are a priority order, not a sequence of steps — #1 is where the hours went.

  1. Tableflow BYOS needs sts:TagSessionBlocker
    Confluent assumes the role with session tags. The trust policy needs two statements: sts:AssumeRole gated by the sts:ExternalId condition, and sts:TagSession with no condition. Miss the second and it fails with the misleading “Unable to assume the IAM role” — even when the principal and ExternalId match perfectly.
  2. Have all five prerequisites ready up frontSetup
    AWS creds, a Cloud resource-management key, confluent login, a running Docker daemon, and Java 21 + a venv. Missing any one stops the run cold on the stage that needs it.
  3. AWS creds are temporary and expireGotcha
    They live only in gitignored aws-session.env (cloud key in cc-session.env), never in .env or git. Sudden 403s mid-run usually mean refresh the STS token first.
  4. Drive DB2 through docker exec -u db2inst1 + db2profileGotcha
    Under amd64 emulation DB2 is flaky. Always docker exec -u db2inst1 … bash -lc '. ~/sqllib/db2profile; db2 connect to TESTDB; …'. Never su - db2inst1 (loses the instance attachment). The healthcheck is known-broken — “unhealthy” ≠ down.
  5. The Glue table keeps the hyphenGotcha
    It registers as orders-enriched, not orders_enriched. Spark must back-tick quote it and set glue.skip-name-validation=true. It also carries extra $$topic/$$offset Kafka-metadata columns beside the real ones.
  6. Only BYOS syncs to an external catalogDesign
    Custom storage (BYOS) syncs to Glue; Confluent-managed storage can only use the built-in Iceberg REST Catalog. Querying from open-source Spark is why BYOS + Glue is the right call — don’t switch to managed storage and expect Glue.
  7. Tableflow has flush latency — give it rows and timeGotcha
    The Iceberg table appears only after enough rows accumulate and the first commit fires. Confirm with aws s3 ls s3://<bucket>/ --recursive | grep metadata.json before running Spark; don’t call it broken at t+30s.
  8. Stale Schema Registry subjects break Flink CTASGotcha
    A leftover orders-enriched-value subject makes the statement FAIL with “subject doesn’t match existing”. Hard-delete the stale subject, then recreate the statement. Same family: SR 401s right after minting keys are just propagation delay — wait.
  9. The verification tooling itself has trapsGotcha
    On macOS there’s no timeout command (use background + sleep + kill); the consume flag is --schema-registry-endpoint, not --sr-endpoint; and consume reads from latest by default. All three make flowing data look missing.
  10. The two ends of the lineage are externalExpected
    DB2 (source) and Spark (consumer) don’t appear in Confluent Stream Lineage — only the middle span does. That’s expected, not a bug; stitching the ends together is the planned OpenLineage phase.
…and more

The rest, grouped by where you’ll meet it

Docker · DB2

  • colima for the daemon: colima start --vm-type vz --vz-rosetta --cpu 4 --memory 8. If the VM is stale, colima delete -f then start fresh. (It’s --vm-type vz, not --vz.)
  • compose plugin: brew install docker-compose then symlink into ~/.docker/cli-plugins/ so docker compose resolves.
  • Seeding rows: copy SQL into the container and run db2 -tvf /tmp/init.sql after sourcing db2profile — not through a host client.
  • Chose JDBC polling over Debezium CDC on purpose — avoids the fiddly DB2 ASN capture setup.

Kafka Connect

  • Self-managed worker → Confluent Cloud over SASL_SSL; the worker’s internal topics must be created on CC with replication factor 3.
  • Avro value converter pointed at Schema Registry; the DB2 jcc driver is baked into the Connect image alongside kafka-connect-jdbc.
  • Source config: mode=incrementing on ID, schema.pattern=DB2INST1, a RegexRouter SMT to name the topic db2-orders.
  • A RUNNING task with an advancing offset is the real proof rows are being produced — check /connectors/db2-orders-source/offsets.

Flink SQL

  • Use CTAS, not INSERT INTO an existing table — CTAS creates the target + schema from the projection and sidesteps the implicit key BYTES “different number of columns” error.
  • --database <CLUSTER_ID> is required for unqualified table names; pair with --wait when scripting.
  • Column names arrive UPPERCASE (DB2 columns via the Avro converter) — write SQL accordingly.
  • “RUNNING” isn’t proof of flow: a statement can read RUNNING with null latest-offsets. Verify by data landing in the output topic, not by status alone.

Tableflow · AWS

  • Two integrations: a provider integration (cspi-*) returns Confluent’s ARN + ExternalId; a catalog integration (tci-*, kind=AwsGlue) with a custom database points Iceberg metadata at Glue.
  • The REST API changed: storage.kind=CustomerManaged is no longer valid. Enable via the CLI: confluent tableflow topic enable … --storage-type BYOS.
  • record_failure_strategy=SUSPEND means a failed assume-role suspends the topic. After fixing the trust policy, disable then re-enable to retry.
  • Verify against live docs — Tableflow moves fast; don’t trust patterns from older Tableflow projects.

Spark · Iceberg

  • JARs: iceberg-spark-runtime-4.0_2.13-1.10.1 + iceberg-aws-bundle-1.10.1; catalog = GlueCatalog, IO = S3FileIO.
  • Auth: EnvironmentVariableCredentialsProvider — so source aws-session.env before submitting.
  • spark-submit comes from the venv (.venv/bin/spark-submit, installed with the pyspark pip package), not the system PATH.
  • No-JVM alternative: pyiceberg (load_catalog(…).load_table().scan()) for a quick sanity read.

Secrets · git · data

  • Secrets hygiene: STS creds in aws-session.env, cloud key in cc-session.env — both gitignored, chmod 600, never in .env.
  • Pushing to a personal repo is blocked by Airlock — use git push-external, don’t bypass it.
  • Decimal display quirk: the CLI consumer renders Avro decimals as fractions (3278/25 = 131.12). It’s a display artifact only — Spark reads proper decimals (2499.75).
  • Sanity check the output: RISK_TIER over 320 rows came out HIGH 96 / $479,991.68, MEDIUM 160 / $163,507.20, LOW 64 / $11,198.40.

Lineage · Marquez (phase 2)

  • macOS AirPlay squats on port 5000: Control Center returns 403 there, shadowing Marquez even though its container is healthy. Map the API to host 5002; the UI on :3000 reaches it over the Docker network, so it's fine.
  • One OpenLineage job per hop (Connect / Flink / Tableflow / Spark); Marquez stitches the DAG purely by matching (namespace, name) on dataset I/O. That's how the four events form one graph — and how you include the DB2 + Spark ends the auto-bridge drops.
  • Pin marquez-web to the released tag 0.51.1 (React 18). main is on React 19 and crashes the UI ("Element type is invalid … Sidenav").
  • The typed labels are a one-line patch: marquez-web hard-codes JOB/DATASET in the node components — swap for a nodeTypeLabel(namespace). Also set devServer.client.overlay.warnings=false so a harmless warning doesn't blank the page.
  • No-Node fallback: make lineage-view renders a typed graph (lineage/graph.html) straight from the Marquez API — handy when you can't build marquez-web.
Copy-paste

The five that save the most time

1 · IAM trust policy — the TagSession statement is the one everyone forgets
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::851725421142:role/cspi-XXXXX" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "<external-id>" } } },
    { "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::851725421142:role/cspi-XXXXX" },
      "Action": "sts:TagSession" }          <- no condition, and easy to omit
  ]
}
2 · Spark — back-tick the hyphen, skip name validation
# in spark_read.py
.config("spark.sql.catalog.glue.glue.skip-name-validation", "true")
# then
spark.table("glue.olpipe.`orders-enriched`")
3 · Consume — the flags that actually exist
confluent kafka topic consume orders-enriched --from-beginning \
  --value-format avro \
  --schema-registry-endpoint "$SR_URL" \      # NOT --sr-endpoint
  --schema-registry-api-key "$SR_API_KEY" \
  --schema-registry-api-secret "$SR_API_SECRET"
# no `timeout` on macOS -> background the consumer, sleep, kill $PID
4 · DB2 — the only invocation that reliably works
docker exec -u db2inst1 olpipe-db2 bash -lc \
  '. ~/sqllib/db2profile; db2 connect to TESTDB; db2 -tvf /tmp/init.sql'
# NOT: su - db2inst1 -c 'db2 ...'   (loses the instance attachment)
5 · Marquez → lineage (port 5002, not 5000)
make marquez-up          # Postgres + API :5002 + UI :3000
make lineage             # emit the full DB2→Spark DAG
make marquez-ui          # patched UI on :3000, typed labels (pins marquez 0.51.1)
# API is on :5002 because macOS AirPlay owns :5000. UI graph:
# http://localhost:3000/lineage/job/flink%3A%2F%2Fenv-m2qxq/olpipe-enrich-orders
